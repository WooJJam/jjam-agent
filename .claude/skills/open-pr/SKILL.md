# /open-pr — PR 작성 (승인 게이트 포함)

작업 완료 후 PR을 여는 절차. `/open-pr` 명령어로 호출됐을 때만 실행한다.
시작 전에 `gh auth status` 확인, 실패 시 `gh auth login` 안내 후 중단한다.

## 사전 체크 0 — 인자·의도 검증 (최우선)

명령어 인자(ARGUMENTS)를 다른 무엇보다 먼저 해석하고 검증한다:

- **인자 없음** → 현재 체크아웃된 브랜치가 대상
- **브랜치명 또는 이슈 번호 지정** → 해석 결과("`<브랜치>` 기준, 이슈 #N 연결 PR")를
  명시하고 진행. 지정 브랜치는 원격에 푸시돼 있어야 하며(아니면 보고 후 중단),
  생성 시 `gh pr create --head <브랜치>` 사용
- **인자가 이 스킬의 목적(PR 작성)과 상반되거나**(예: "이슈 생성", "머지해줘",
  "브랜치 삭제"), **모호하거나, 해석이 두 가지 이상 가능하면** — 멋대로 판단해서
  진행하지 않는다. **반드시 사용자에게 질문해**(AskUserQuestion 또는 텍스트)
  의도를 확인한 뒤에만 진행한다. "아마 이런 뜻이겠지"로 절차를 시작하는 것 자체가
  금지다.

## 사전 조건

- 대상 브랜치가 `main`이 아니어야 한다 (main이면 중단)
- 브랜치명 `<타입>/<이슈번호>-<슬러그>`에서 이슈 번호를 파싱한다.
  파싱 불가(번호 없는 브랜치)면 사용자에게 연결할 이슈 번호를 묻는다
- (현재 브랜치 대상일 때) 미커밋 변경이 있으면 처리 방법(커밋/제외)을 사용자와
  정한 뒤 진행

## 모드 결정 — 열린 PR 존재 확인

`gh pr view --json state,url,body` 로 대상 브랜치에 이미 열린 PR이 있는지 확인한다.

- **없음** → **신규 모드**: 아래 절차 1~6
- **열려 있음** → **업데이트 모드**: 아래 "업데이트 모드" 절 — 새 PR을 만들지 않고
  기존 PR 본문에 수정 사항을 누적한다. `gh pr create` 재시도 금지

## 절차

### 1. 이슈 대조

`gh issue view <번호>`로 연결 이슈를 읽고, "작업 항목" 체크리스트와
`git log origin/main..HEAD` + `git diff origin/main...HEAD --stat`를 대조한다.

- 완료된 항목/미완료 항목을 구분해 보고
- 미완료 항목이 있으면 그대로 PR을 열지, 작업을 더 할지 사용자에게 확인

### 2. 시크릿 최종 검사

`git diff origin/main...HEAD`에서 다음을 검사하고, 하나라도 발견되면 **PR을 열지
않고 중단**해 보고한다:

- 시크릿 패턴: `sk-`(OpenAI), `gho_`/`ghp_`(GitHub), `AKIA`(AWS),
  `BEGIN ... PRIVATE KEY`, Discord 토큰형 문자열
- 금지 파일: `.env*`(`.env.example` 제외), `*.xlsx`, `data/` 내용물, `*.db`

### 2.5 컴파일·테스트 검증

PR 초안을 작성하기 전에 실행한다:

1. **컴파일**: 브랜치에서 변경된 `.py` 전체를 `py -m py_compile`로 검증
2. **테스트**: `py -m unittest discover -s tests` 실행 (tests/ 디렉터리가 있을 때)

- 하나라도 실패하면 **PR을 열지 않고** 실패 내용을 보고한다. 수정 후 이 단계부터 재시작
- 변경분에 `.py`가 없으면(문서·설정만) "테스트 대상 없음"으로 보고하고 진행
- 통과 결과(테스트 수·소요)는 PR 본문 `## 검증` 섹션에 기록한다

### 3. PR 초안 작성

- 제목: 커밋 컨벤션 형식 `타입(스코프): 요약 (#이슈번호)` — squash 머지 시
  그대로 커밋 메시지가 된다
- 본문 구성:
  - `## 요약` — 무엇을 왜 (1~3문장)
  - `## 변경` — 파일·변경점 목록
  - `## 이슈 체크리스트 대조` — 1단계 결과 (완료/미완료 표시)
  - `## 검증` — 2.5단계 결과 (컴파일·테스트 통과 수)
  - `Closes #<이슈번호>` — 머지 시 이슈 자동 클로즈
  - `🤖 Generated with [Claude Code](https://claude.com/claude-code)` 트레일러
  - 맨 끝에 동기화 마커 `<!-- last-sync: <현재 HEAD SHA> -->` — 업데이트 모드의 기준점
- 라벨: 연결 이슈와 동일하게 부여 (사전 정의 11종만, 신규 생성 금지)
- 베이스: `main`

### 4. 승인 게이트 (필수)

PR 제목·본문 전문·베이스 브랜치·라벨을 한 번에 보여주고 사용자 승인을 받는다.
승인 없이 `gh pr create`를 실행하지 않는다. 수정 요청 시 반영 후 재확인.

### 5. PR 생성

본문을 스크래치패드 임시파일(UTF-8)로 저장한 뒤:

```bash
gh pr create --base main \
  --title "타입(스코프): 요약 (#번호)" \
  --body-file "본문파일경로" \
  --label "타입" --label "도메인"
```

푸시 안 된 커밋이 있으면 생성 직전에 `git push`한다 — push도 이 절차의 일부로
승인 게이트 이후에만 실행한다.

### 6. 보고

PR URL을 보고한다. **머지는 이 스킬 범위 밖** — 사용자가 직접 하거나 별도 지시
시에만 `gh pr merge --squash`를 실행한다.

## 업데이트 모드 — 리뷰 반영 재호출 시

이미 열린 PR이 있는 브랜치에서 호출된 경우. 새 PR을 만들지 않고 기존 PR을 갱신한다.

1. **기준점 파싱**: PR 본문의 `<!-- last-sync: SHA -->` 마커에서 마지막 동기화
   커밋을 읽는다. 마커가 없으면 `origin/<브랜치>` 위치를 기준점으로 폴백
2. **변경분 수집**: `git log <기준점>..HEAD --oneline` — 이 커밋들이 이번에 반영할
   내용. 새 커밋이 없으면 "반영할 변경 없음"을 보고하고 종료
3. **재검증**: 신규 모드와 동일하게 시크릿 검사(2단계) + 컴파일·테스트(2.5단계)를
   새 변경분에 대해 실행. 실패 시 중단
4. **승인 게이트**: 추가될 불렛 목록(커밋 제목 + SHA, 리뷰 대응 맥락 한 줄)을
   보여주고 사용자 승인을 받는다. 승인 없이 push·PR 수정 금지
5. **반영**: `git push` → `gh pr edit --body`로 본문 하단 `## 수정·반영 사항` 섹션에
   차수를 붙여 append (기존 본문·이전 차수는 보존):

   ```markdown
   ## 수정·반영 사항
   ### 2차 (YYYY-MM-DD)
   - fix(scope): 리뷰 지적 대응 내용 (SHA)
   ```

   마커를 현재 HEAD로 갱신: `<!-- last-sync: <새 SHA> -->`
6. **보고**: PR URL과 추가된 차수·불렛 수를 보고한다

## 금지 사항 (Anti-patterns)

- 인자·의도 검증(사전 체크 0) 생략 — 인자가 목적과 어긋나는데 질문 없이 진행
- 승인 게이트(4단계·업데이트 4단계) 없이 PR 생성·수정 또는 push
- 시크릿 검사(2단계)·컴파일·테스트 검증(2.5단계) 생략
- 열린 PR이 있는 브랜치에서 `gh pr create` 재시도 (업데이트 모드를 써야 함)
- 미완료 체크리스트를 숨기고 PR 생성
- 머지 자동 실행, main 직접 푸시, force push
- 이슈 연결(`Closes #N`) 누락
